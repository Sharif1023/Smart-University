# Student Portal audit

Audit date: 2026-11-21. The repository is an existing React + TypeScript client, Express 5 API, and MySQL 8 application using `mysql2/promise`. The portal uses hash-based navigation, one role-aware operations API, a consolidated MySQL schema and SQL seed, and server-side role/object checks. This audit describes the implementation present before the feature work documented in `STUDENT_PORTAL_IMPLEMENTATION.md`.

**Verification meaning:** `Lint/build` means source lint and the production build completed. `Live` means the route and database workflow was exercised against the configured MySQL-compatible server. This is the pre-change inventory; final verification is recorded below and in `TEST_RESULTS.md`.

## Stack inventory

- Client: React 19, TypeScript, Vite; hash-based routing; shared dynamic service forms/tables.
- API: Express 5, native ESM, `mysql2/promise`; session authentication and one role per account.
- Database: MySQL 8.0.16+, consolidated SQL schema and seed; no ORM.
- Files: small thesis/notice PDFs stored as database blobs with authorization checks.
- Integrations: no configured mail/SMS, payment gateway, object storage, ML service or LLM provider.
- Tests: Node test runner, Playwright browser tests, static lint/typecheck/build.

## Implementation status update

The table above records the mandatory pre-change audit. After implementation, the previously missing profile editing/photo, exam schedule, attendance correction request, published-grade review, document request tracking, student support, library reservation/renewal, notification preferences and career workflows now have MySQL schema, API/workspace forms and role-scoped authorization in source. Students can also export published grades as a CSV. The Academic Assistant now has upcoming-exam, assessment-deadline and overdue-loan intents; a browser-only what-if GPA calculator is available to students. Setup, seed verification and all seven core-role login flows passed on the local MySQL-compatible server; the new workflows were not each tested end to end. See [STUDENT_PORTAL_IMPLEMENTATION.md](STUDENT_PORTAL_IMPLEMENTATION.md) for the updated matrix and remaining incomplete items.

The project uses the MySQL protocol and `mysql2/promise`. The configured local database is MariaDB 10.11.19 on port 3306. Schema setup, seed verification and core-role login were exercised there after the fixes; broader workflow suites still require a separate `_test` database.
